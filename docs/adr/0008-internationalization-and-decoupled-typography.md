# 0008: Internationalization and Decoupled Typography

## Context & Decision
To ensure that SVG Maestro is universally adopted by developers and designers across global open-source and enterprise environments, we decided to establish an explicit **Internationalization (i18n) Architecture**:
1. **Canonical English Repository & Code**: Repository documentation (`README.md`), the skill specification (`SKILL.md`), and internal SVG attributes (IDs, classes, and `inkscape:label`) are maintained in canonical English. Localized community guides (e.g. `README.pt-BR.md`) are maintained alongside.
2. **Polyglot Conversational Agent**: The agent automatically detects the user's conversational language, conducting the interactive briefing (`ask_question`) and critique feedback in the user's native tongue while generating standard English XML tokens.
3. **Decoupled Vector Typography**: Generated text elements must NEVER be outlined or converted to vector paths (`path`). All labels, headings, and data readouts must remain semantic `<text>` nodes isolated in a dedicated Inkscape layer (`inkscape:label="Typography & Labels"`), supporting native browser multilingual selection via `<switch>` and `systemLanguage`.

## Considered Options
- *Converting Text to Path Outlines*: Rejected because vector paths destroy text searchability, screen reader accessibility, and multilingual translation in Inkscape and code.
- *Strictly English-Only Agent Conversations*: Rejected because international creators must be able to articulate aesthetic intent and answer briefing questions in their native language.

## Consequences
- Every SVG asset generated by SVG Maestro is easily translatable via text replacement or Inkscape's text tool.
- The repository and tools welcome both Brazilian and international developer communities seamlessly.
